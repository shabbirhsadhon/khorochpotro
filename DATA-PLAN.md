# Data Plan

Core data is user input stored in the artifact's own per-account database (users, sessions, entries, budgets) and served by its own actions — no external content sources.

One self-referential export: the `exportSourceArchive` action (signed-in users only) asks a privileged host function to read this project's own source tree from disk (client/, server/, drizzle/, root config files), zip it in memory, and return it base64-encoded so the user can download the ZIP and push it to GitHub. The archive deliberately excludes all user data and runtime state: app.db and its journals, node_modules, build output (client/dist, client/dist-cvm, server/dist), .space-build*, .harness, audits, and blobs are never included. It adds a generated README.md and .gitignore when the tree lacks them.

One user-configured external destination: the GitHub encrypted backup. When the user enters their own GitHub repo (`owner/repo`), a personal access token, and a backup passphrase in the app's backup setup, the client encrypts the full ledger — all entries plus the budgets (the legacy every-month `budgetPoisha` and every per-month budget in `budgets: [{month, monthlyPoisha}]`, mirroring the original app's per-month budgets stored server-side in `budget_months`) — on-device (AES-256-GCM, key from PBKDF2-SHA256, 150k iterations) and writes it through the GitHub Contents API (`https://api.github.com/repos/<repo>/contents/backup/khorochpotro-<sha256(email) first 16 hex>.json`). GitHub only stores the encrypted envelope; the token and passphrase live only in the device's localStorage and are never sent to the app server. Restore reverses the flow: fetch, decrypt on-device, import entries through the normal `importEntries` action and apply the stored budgets through `setBudget` — each per-month budget with its `month`, the legacy budget without one (backups written before budgets were included carry neither field and leave the current budgets untouched). After any ledger change, a debounced auto-backup refreshes the GitHub copy when setup exists.
